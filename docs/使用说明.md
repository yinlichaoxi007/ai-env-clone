# AiEnvClone 使用说明

> AiEnvClone 是一款跨电脑备份 / 迁移**国内** AI 编程工具记忆、历史、配置的小工具。它同时提供命令行与图形界面（tkinter），对运行环境**零第三方运行时依赖**，可打包为单文件 exe 直接拷贝到没有 Python 的 Windows 电脑上运行。
>
> 当前已支持 **8 个**工具：Qoder CN（插件与桌面端）、CodeBuddy CN、Reasonix、DeepSeek Harness（DSH）、WorkBuddy、TraeCode CN、TraeWork CN、ZCode。各工具的数据目录、备份范围、跨电脑处理细节不同，由内置的「适配器」分别处理——**你只需在界面顶部选对要备份 / 迁移的工具，其余交给本工具**。
>
> 除整库备份 / 还原外，还支持**跨软件会话导入**：把另一个软件的历史会话，按当前所选工具的**原生格式**写出（见第 4.3 节）。

---

## 1. 功能特性

- **多工具支持**：同一套界面备份 / 还原不同的国内 AI 编程工具，顶部「AI 工具」下拉切换（共 8 个）。
- **跨软件会话导入**：把其它软件的会话按**当前工具的原生格式**写出（明文可读会话才支持；加密主库工具只能整库备份 / 还原）。
- **跨电脑还原**：自动处理「登录用户 UUID 重映射」「全局索引文件合并」「深层长路径」等跨机器陷阱（见第 6 节），让你换电脑后历史会话、记忆、工作区都能正常打开。
- **默认不破坏目标**：还原采用「只增不删」策略，不覆盖目标机器已有的同路径数据（见第 5、6 节）。
- **增量 / 可选项**：默认勾选「会话 / 记忆 / 规则」+「设置 / 技能 / 灵感 / 模型配置」，让还原后**立刻能开工**；插件 / 扩展 / MCP / 索引按需自选；本地缓存 / 日志 / 凭证不备份；**技能只备份本机技能数据，技能市场数据（本地镜像、目录索引）不备份**（判据与完整分类见 README「备份范围与默认勾选策略」）。
- **单文件 exe**：无需安装 Python，双击 `dist/AiEnvClone.exe` 即可使用。

## 2. 支持的工具与运行环境

| 工具 | 显示名 | 数据目录（示例） | 备注 |
| --- | --- | --- | --- |
| Qoder CN（JetBrains 插件） | Qoder CN | `~/.qoder-cn` | 含 `shared_client` 多 UID；会话主库加密 |
| Qoder CN IDE（桌面客户端） | Qoder CN | `~/.qoder-cn` + `%APPDATA%\com.qodercn.app.stable` | 新版为 Electron，历史在 `main.sqlite` |
| CodeBuddy CN | CodeBuddy CN | 项目级 `<project>/.codebuddy` + 全局 `~/.codebuddycn` | 记忆区单用户扁平 |
| Reasonix | Reasonix | `%APPDATA%\reasonix`（配置）/ `%LOCALAPPDATA%\reasonix`（缓存） | 会话位于 `projects/<scope>/sessions/` |
| DeepSeek Harness | DeepSeek Harness | `~/.dsh` | 工作区名依赖全局索引 `workspace.json`；导入需 zstd 后端 |
| WorkBuddy | WorkBuddy | `~/.workbuddy` | 会话索引在中央库 `workbuddy.db` |
| TraeCode CN | Trae CN（安装目录） | `%APPDATA%\Trae CN` + `~/.trae-cn` | 会话主库**产品侧加密**，仅整库备份 |
| TraeWork CN | TRAE SOLO CN（安装目录） | `%APPDATA%\TRAE SOLO CN` + `~/.trae-solo-cn` | 同上，家族共享实现 |
| ZCode | ZCode | `%USERPROFILE%\.zcode`（新版 CLI）/ `<HOME>\.zcode\v2`（旧桌面） | 会话为普通 SQLite；不支持「导入到 ZCode」 |

> 表中目录为各工具默认位置，实际以本机为准。界面「数据目录」区会列出所选工具探测到的真实路径与「当前用户」标识。
> **哪些工具能互相导入会话？** 明文可读（JSONL / JSON / 普通 SQLite）的会话才能跨软件转换；Qoder 与 Trae 家族的会话主库是**产品侧加密**的，只能整库不透明备份 / 还原。界面「数据导入」区会针对当前所选工具直接列出可导入的来源、版本与数据范围。

**运行环境要求**：

- Windows 10/11（主要支持）；macOS / Linux 可运行源码模式、可执行 `build_exe.py` 在本平台打包对应产物。
- 图形界面：Windows 需有 Python 3.10+（源码模式）或直接使用打包好的 exe。
- 无需安装任何第三方 Python 包。

## 3. 安装与启动

### 方式一：使用打包好的 exe（推荐，目标电脑无需 Python）

1. 复制仓库里的 `dist/AiEnvClone.exe` 到目标电脑任意目录。
2. 双击运行即可。

### 方式二：源码模式（开发 / 调试）

1. 安装 Python 3.10+ 并加入 PATH。
2. 双击 `run.bat`，或命令行执行：

   ```powershell
   python -m ai_env_clone
   ```

> `run.bat` 的逻辑：若 `dist/AiEnvClone.exe` 存在则优先启动它，否则退回源码模式。

### 重新打包 exe

改动了源码后，若要生成新的 `dist/AiEnvClone.exe`，双击 `build.bat`（内部用 `build_exe.py` 调 PyInstaller 单文件打包）。各平台需各自打包，不能交叉编译。

## 4. 界面说明

启动后主界面大致分为如下区域（示意见下方截图）：

1. **AI 工具**：顶部下拉，切换要备份 / 迁移的 AI 工具（Qoder CN / CodeBuddy CN / Reasonix / DeepSeek Harness / WorkBuddy / TraeCode CN / TraeWork CN / ZCode）。切换后「数据目录」「备份内容」「数据导入」「当前用户」等区域会按所选工具刷新。
2. **数据目录**：显示所选工具探测到的数据目录列表，以及「当前用户」标识（登录用户 UUID 等）。可手动增删目录后再备份 / 还原。
3. **备份内容**：勾选项，决定本次备份包含哪些数据（会话、记忆、规则、插件、设置等）。各工具的默认勾选由适配器决定，判据是**重新获取的成本**：会话 / 记忆 / 规则，以及设置 / 技能 / 灵感 / 模型配置默认勾选（让还原后立刻能开工）；插件 / 扩展 / MCP / 索引按需自选；缓存 / 日志 / 运行态 / 凭证不列入。**技能只备份本机技能数据，技能市场的本地镜像与目录索引不备份**（可重新下载）。
4. **数据导入**：随所选工具刷新，直接列出**该工具可导入的来源软件、实测版本、可导入的数据范围与状态**。
5. **压缩方式**：备份包压缩级别（如 仅存储 / 标准压缩）。仅影响体积与打包耗时，不影响还原结果。
6. **选项**：如「严格校验模式」（还原前对备份完整性做更严格检查）等开关。
7. **操作按钮**：「备份」「还原」以及进度 / 日志展示。
8. **仅特定工具显示的行**：选中 **DeepSeek Harness** 时在数据目录区出现「会话健康」行（见 6.4）；选中 **Qoder CN** 时出现「历史会话诊断」行（见 6.5）。对其他工具隐藏。

## 5. 备份与还原

### 5.1 备份（同电脑 / 换电脑前）

1. 顶部「AI 工具」选对要备份的工具。
2. 确认「数据目录」区域列出的路径无误（可手动增减）。
3. 在「备份内容」里勾选要包含的数据；其余保持默认即可。
4. 选择「压缩方式」。
5. 点「备份」，选择输出 zip 路径（默认形如 `<工具>_backup_<时间戳>.zip`）。

备份产物是一个普通 zip，可拷贝到 U 盘 / 另一台电脑。

> **敏感凭证提醒**：部分「设置类」文件（CodeBuddy/WorkBuddy 的「自定义模型配置」`models.json`、Reasonix 的 `config.toml` 等）可能直接含明文敏感凭证（apiKey、令牌、私人令牌等）。这类条目**默认就勾选**，所以默认备份包也必须保证不外泄：导出时对敏感字段做**脱敏占位**（`***REDACTED***`，只换值、不动键名与格式），包内不含明文凭证，但配置条目仍保留。还原到目标机器后需在源机记下、并在目标机手动补填这些凭证，否则对应模型/服务虽可见但无法使用。（环境变量引用形式（如 `${MY_API_KEY}`）原样保留，跨电脑只需目标机有同名环境变量即可。）
>
> **「引用」不算凭证，不会被抹掉**：像 `apiKeyEnv: MY_KEY_ENV`、`keyFile: …\keys\id_rsa` 这类键，值是**环境变量名或路径**，本身不含密钥——抹掉它反而会把配置改坏（还原后指向一个不存在的变量名，模型静默失效）。所以凡键名含 `Env` / `File` / `Path` / `Var` / `Dir` / `Name` 的，值一律原样保留。
>
> **密钥存在独立文件里的工具，会提醒你单独备份**：DSH 即如此——`~/.dsh/settings.yaml` 里只写 `apiKeyEnv`（引用名），真密钥在同目录 `.credentials.yaml` 的 `refs` 段。该文件含明文、默认不勾（随包分享会外泄），因此当你勾了 `settings.yaml` 却没勾它时，备份完成提示会明确告诉你「模型密钥在哪个文件、要不要单独备份」。
>
> **自动定位（默认开启）**：备份选项中「备份后定位敏感文件」默认勾选。若本次备份包含脱敏项，完成后本工具会**自动打开该文件所在文件夹并高亮文件、用默认编辑器打开文件，并尝试把光标定位到敏感字段（如 apiKey / 令牌）所在行**（已安装 VS Code 时通过 `code -g` 精确跳转），方便你手动记下凭证。不想自动打开文件时取消该勾选即可，届时仅弹文字提醒。

> **备份包会携带源机器的路径等信息（请在分享前留意）**：这不是本工具新加的东西，而是「会话与记录本身自带的」——会话正文、命令输出、文件快照里会留下当时的文件绝对路径（实测 CodeBuddy `history/**` 24519 个 JSON 中 20564 个命中），归档内的目录结构还会带上源机器的用户名与登录用户标识（如 `…\Users\<用户名>`、`Data/<登录用户 uuid>/…`）。
>
> 这些信息**有价值**：它们正是「还原后把会话/数据归回它原本的工程工作区」的依据。但反过来，**把备份包分享、上传或发给他人时，它们会一并外传**。
>
> 本工具在三个地方把它说明白，不用你事后才发现：
> 1. **备份内容**里那一行——若该项会携带源设备信息，行内直接写明「携带源设备信息：…」（勾选那一刻就是决定「要不要把包发出去」的时刻）；
> 2. **备份完成后**的提示框——列出本次包内各条目携带了哪类源设备信息；
> 3. **备份包详情**（备份浏览器右侧）——新增「携带的源设备信息」一节，逐条列出；还原前的确认框也会先说一句。
>
> 另外，「**IDE 工作区记录（已打开文件夹）**」（CodeBuddy CN 与 Trae 家族下位于 `%APPDATA%\<产品名>\User\workspaceStorage\*\workspace.json`，每个仅 50~70 字节）是**默认勾选**的备份项：它记录「哪个工程文件夹对应哪个工作区」，是跨机还原后把会话正确归回原工程工作区的**唯一结构化映射**（CodeBuddy 的会话按 `md5(项目路径)` 索引，哈希不可逆；Trae 的会话库则整库加密、连哈希都没有）。丢掉它就只能靠会话正文去猜了 —— 而 Trae 那边连正文都取不出来。
>
> 提醒一点：这条记录**只覆盖「在源机器上把工程作为文件夹打开过」的情况**。如果某台机器上从没这样打开过（本机实测 Trae 就是这样，只留了一个空窗口目录、连 `workspace.json` 都没有），那这份信息在源头就不存在，任何备份都带不出来。
>
> 更进一步，**只要勾了「集中会话」，导出时还会自动附带一份「会话 → 原始工作区路径」映射**（包内 `…/CodeBuddyIDE/<uid>/session-workspaces.json`，本机也留一份）。它把每个工作区原本的工程路径**显式**记下来，随包携带、还原后落回原位，因此**不依赖「先还原 IDE 记录、再导入会话」这个顺序**；实在推不出路径的条目，也会保留会话正文里的**候选路径**（只是线索、不自动采用）。实测本机 21 个工作区里只有 1 个能还原出具体路径 —— 所以推不出来的那些由「导入前显式确认」兜底，见 5.3。

### 5.2 还原（换电脑 / 重装后）

1. 顶部「AI 工具」选**与备份时相同**的工具。
2. 点「还原」，选择备份 zip。
3. 确认「数据目录」指向**本机**该工具的数据目录（不是源电脑路径）。
4. 按需勾选「选项」（如严格校验）。
5. 点「开始还原」。

> **还原采用「只增不删」原则**：不会删除目标机器已有的、备份里没有的数据；对于被备份覆盖的文件，若该文件属于「可合并」类型（见 6.2），会合并而非整体覆盖；否则以「目标已有则不破坏、仅补入缺失」的方式处理。

> **还原会把包内携带的源设备信息写回本机对应位置**：例如「IDE 工作区记录」会落回本机 `%APPDATA%\<产品>\User\workspaceStorage\`，「会话原始工作区映射」会落回本机 `…/CodeBuddyIDE/<uid>/session-workspaces.json`（这两样都是让会话能归回原工程工作区所必需的）。确认框里会先说明本包带了多少处；不想写回这些文件时，可到「备份内容」里取消勾选对应条目后重新备份。

### 5.3 跨软件导入会话（把另一个软件的会话搬到当前工具里）

> 本节对应界面第 4 区的「数据导入」。它与备份 / 还原互补：备份 / 还原解决**同一个软件**跨电脑迁移；跨软件导入解决**把一个软件的会话搬进另一个软件**。

1. 顶部「AI 工具」选**导入的目标工具**（当前支持导入的有：Reasonix、CodeBuddy CN、WorkBuddy、DeepSeek Harness）。
2. 看「数据导入」区列出的可导入来源与版本；点「导入说明」可查看全部工具的支持矩阵。
3. 点「导入会话…」，在弹出的对话框里：
   - 选**来源软件**（来源目录一般已自动填好，可改）；
   - 等它**扫描出可导入会话**，在列表里选中会话（按住 `Ctrl` / `Shift` 可**多选**，一次导入多条）；
   - **目标工作区不用填**——它默认自动判定，界面上只读展示**实际会落到的那个工作区**（单选显示具体落点；多选且落点不一致时只提示「存在多个工作区」，不挑一条显示）；
   - 点「导入选中会话」。
4. 导入在后台执行，完成后弹「导入完成」并给出**每条会话的新 id**（多条时列出明细）。若落点存在风险（如路径在目标机不存在且未创建），会再弹一个**注意事项**框汇总提示——但会话**已经写入**，这些提示不阻断。

**目标工作区是怎么自动判定的**（`原因 → 结果`）：

| 情况 | 落点 |
| --- | --- |
| 源会话**自带工作区**（多选时逐条判定） | 直接沿用源会话的工作区，尽量与源机器路径同源 |
| 源会话**只记了「派生 id」形态的工作区**（CodeBuddy 的 `workspaceId` = `md5(项目路径)`） | 先把它还原成项目路径（见下方说明）：① **备份包自带的「会话原始工作区映射」**；② 本机 IDE 记过的「已打开工程」；③ 会话正文里出现过的路径候选 + 哈希校验。任一成功就按上一行走；**都还原不出来**才用默认落点 —— 而且**导入前会弹框明确告诉你**（见下），并把候选路径列出来给你挑 |
| 源会话**没有工作区** | 用该工具「无工作区会话」的默认落点：Reasonix → `global-workspace`；CodeBuddy CN → 固定的 `imported-sessions` 工作区；WorkBuddy → `~/WorkBuddy/<时间戳>`（与产品自身的 playground 一致）；DSH → 用户主目录 `~` |
| 你**勾选了「手动指定工作区」** | 本次导入的**全部**会话都落到你指定的那一个工作区，**包括本身就自带工作区的会话** |

- **CodeBuddy 的 `workspaceId` 是哈希，不能当路径用**：它的会话目录名是 `md5(项目路径小写、反斜杠)`，**不可逆**，而 WorkBuddy / DSH 的落点是**路径**。所以本工具按三条路还原，**只有能验证的才认**：
  1. **备份包自带的「会话原始工作区映射」**（包内 `…/CodeBuddyIDE/<uid>/session-workspaces.json`）：备份时就把「每个工作区原本的工程路径」记进了包，随包携带、还原后落回原位。**这条路不依赖任何本机状态，也不依赖操作顺序**（另两条都要求「先还原、后导入」才生效），所以最优先；
  2. **本机 IDE 记过的「已打开工程」**：读 `<应用数据根>/CodeBuddy CN/User/workspaceStorage/*/workspace.json`（也可由备份包里的「IDE 工作区记录」条目跨机带过来）与 `User/globalStorage/storage.json`，把候选路径按同一规则求 `md5` 与目录名对齐；
  3. **会话正文里的路径 + 哈希校验**：会话的 `index.json` 里没有结构化的路径字段，但正文（`messages/*.json`、`check-point/` 快照）里**大量含绝对路径**（实测本机 24519 个 history JSON 里 20564 个命中），而这两处**都在备份范围内**，所以「另一台机器备份 → 本机还原」后也能用：把挖出的候选逐个求 `md5`，**对得上才算**（md5 碰撞可忽略）。

  三条都还原不出来时（实测这种情况不少：本机 21 个工作区只有 1 个能还原），**退回默认落点前会弹一个确认框**，列出这些会话、点明它们会落到工具默认目录、并附上候选路径；你可以当场选择改用「手动指定工作区」——**不会静默换落点，也不会让你事后才发现**。
- **不猜路径**：正文里出现的候选"哪一段才是工程根"无法可靠判定（实测会推成过深的子目录、IDE 的 playground 目录，甚至把正文里的换行 `d:\n` 当成路径），所以候选**只作为线索**摆给你看：勾选「手动指定工作区」后，输入框下拉里会列出这些候选，一键即可采用——采用后如果本机没有该目录，导入前会照常问你**要不要创建**（对话框里会注明这个路径是「源会话还原」还是「工具默认」）。

- **手动指定会覆盖全部会话**：勾选后输入框旁会常驻一条红色警示；若本次选中的会话里有自带工作区的，导入前还会再弹一次确认框（列出会覆盖几条）。手动框里可填：WorkBuddy / DSH 填工作区路径（可「浏览…」选目录）、CodeBuddy 填 workspaceId（下拉列出目标机已有 id，也可「浏览…」选项目目录自动换算出 id）、Reasonix 填项目名。
- **「目标工作区」这一栏只显示实际会落到的那个工作区**，随你所选的会话实时刷新，并说明它是**从哪来的**：
  - **单选**（或还没选）→ 显示判定出的那一个工作区，并标注「沿用会话自带工作区」或「工具默认（无工作区会话）」；若是在默认落点上、但源会话其实**记了**工作区（只是没能还原成路径），会再补一句成因说明（见上方 CodeBuddy `workspaceId` 一条）；
  - **多选、且各条落点不同** → 只提示「存在 N 个不同的工作区」，**不会挑一条显示**（挑一条容易被误读成统一落点）；若其中有些会话没有自带工作区，会额外说明有几条会落到默认落点；
  - **多选、落点一致** → 显示该落点，并说明它是「各会话自带的工作区相同」还是「都没有记录工作区 / 都没有可还原为路径的工作区、统一落到工具默认落点」。后者会明确标注「自动判定，非手动指定」——因为勾选「手动指定」时的**预填值就是自动判定值**，两者长得一模一样，只给一个路径会被误读成「我上次手动填的没清掉」。
- **没勾选「手动指定工作区」时，手动输入行是整体收起的**（不是置灰留着上次的路径）——遗留的旧路径很容易被误认为本次实际落点。勾选后才会出现输入框，并**预填当前自动判定值**供你微调；若勾了却把内容清空，则仍按自动判定走，预览里会明确写出这一点。
- **落点「推不出来」时会先问你，不会静默换地方**：有些会话（典型是 CodeBuddy 的）原本**有**工作区，但只留下一个不可逆的 id（`md5(项目路径)`），备份包与本机都没能还原成路径。这时**导入前会弹框**：列出这些会话（附工作区 id 前 8 位）、点明它们会落到工具的默认目录（WorkBuddy 还会现造一个带时间戳的新目录），并附上正文里出现过的候选路径。选 `是` 接受默认落点继续；选 `否` 改用「手动指定工作区」（候选已预填进下拉，可一键采用）；选 `取消` 中止导入。
- **工作区不存在不会偷偷创建**：导入前会弹框询问——`是` 先创建目录再导入；`否` 不创建但**仍按原落点导入**（目标工具写出时会自建自己需要的目录）；`取消` 中止本次导入。
- **落点目录名与产品自身完全一致**：WorkBuddy 的 `projects/<工作区编码>` 与 DSH 的 `sessions/<工作区编码>` 都按各产品自己的真实规则推导（含中文路径），所以导入的会话会规规矩矩地归到对应工作区，不会散落到别处。

要点：

- **不会覆盖目标已有会话**：新会话一律使用全新生成的 id。
- **会同时登记目标工具的索引**：WorkBuddy 会写进 `workbuddy.db` 的 `sessions` 表；DSH 会写进 `workspace.json`（**界面列表靠它**），并尽力在新版 `session_projcache*` 缓存里补一条标题记录（该缓存 DSH 可自行从会话日志重建，故写失败不影响结果）。只落文件不登记索引，**界面里是看不到的**。
- **不会改动来源数据**：解析来源一律只读（ZCode 的 `db.sqlite` 以只读方式打开）。
- **DSH 需要 zstd 后端**（`zstandard` / `pyzstd` 模块或系统 `zstd` 命令），缺失时会明确报错而不是静默产生坏数据。
- **ZCode 只能作来源**（可把它的会话导出到别的工具），暂不能作为导入目标——其写出格式未实测确认，为避免写坏它的库故不做。
- **Qoder CN / TraeCode CN / TraeWork CN 不支持跨软件导入**：它们的会话主库是**产品侧加密**的，本工具只能整库备份 / 还原。

## 6. 跨电脑还原的特别处理

不同工具的会话 / 工作区在组织方式上差异很大，直接整包还原到另一台电脑常踩坑。本工具按各工具适配器声明的机制分别处理以下三类典型问题（机制细节见 `README.md` 的「跨电脑还原」章节，这里只讲用户须知）：

### 6.1 登录用户 UUID 自动重映射

部分工具（如 CodeBuddy）的会话按**登录用户 UUID** 分目录存放。换电脑后用户 UUID 不同，本工具会自动把备份里的旧 UUID 重映射为本机当前登录用户 UUID，确保会话落到本机工具实际读取的目录。若本机从未登录过该工具（取不到 UUID），则保持原路径、不破坏备份。

> 用户无需任何操作；只要本机已登录该工具，还原后的会话即可正常打开。

### 6.2 全局索引文件合并

某些工具（如 DSH）的工作区名依赖全局索引文件（而非目录名）。若整体覆盖该索引，会抹掉本机原有工作区、使其变成「未分组」。本工具对这类索引文件走**合并而非覆盖**：保留本机原有条目，并入备份带来的源条目，定位字段（path/title）一律用本机真实路径。

> 用户无需任何操作；还原后源机器迁移来的工作区与本机原有工作区共存，都不会变「未分组」。

### 6.3 深层会话消息长路径修复（Windows）

部分工具（如 CodeBuddy）的会话消息路径层级很深，在 Windows 上易超过 260 字符限制导致读不到。本工具已对所有文件操作加长路径前缀，深层会话消息可完整备份与还原，用户无需关心。

### 6.4 DSH 历史会话「无法加载 / 未分组」的检测与修复（手动维护）

若 DeepSeek Harness 升级后历史会话打不开（报 corrupt / 无法加载）或列表里出现「未分组」，在主界面选择 DeepSeek Harness 后，数据目录区会出现两个按钮：

- **「检测会话健康」**：只读扫描，报告未分组、索引问题、旧格式会话、重复调用 id、子代理描述符不兼容等各类问题的数量；
- **「修复未分组会话」**：先列出将执行的修改（dry-run）供确认，确认后**逐文件自动备份**再写盘。

> **须知**：
> - 修复只处理本工具明确支持的问题——「扁平 replayState 升级（双侧同值，保证会话能正常打开）」与索引归属；「重复调用 id」需勾选复选框才一并处理（会改写数据）。
> - 被标记为「子代理描述符不兼容」的会话**当前暂不修复**（已知无法加载，等后续版本支持）。
> - 修复幂等，重复执行不产生新改动；**绝不删除任何条目**，写盘前均有自动备份。
> - 为什么必须「双侧同值升级」等机制细节见 `README.md` 的「DSH 旧会话『未分组 / 无法加载』检测与修复」章节。

### 6.5 Qoder 新版「导入旧数据后仍看不到历史会话」的诊断

新版 **Qoder CN 已改为独立桌面客户端（Electron）**：数据根从旧的 `~/.qoder-cn` 迁到 `%APPDATA%\com.qodercn.app.stable`，会话主库变成 `main.sqlite`；设置里的「导入旧版数据」入口只搬运它认识的那部分，旧插件的部分记忆 / 项目数据**不会被自动带过去**。所以「导入成功」不等于「历史可见」。

在主界面选择 **Qoder CN** 后，会出现「历史会话诊断」行，点**「检测历史会话」**即可得到一份对照报告：

- 新旧两处**数据根**的实际路径与是否存在；
- 新版 `main.sqlite` 的**会话 / 消息条数**（为空即直接解释了「界面里看不到历史」）；
- 应用内**导入账本** `sessionMigration.sqlite` 的 `import_job` / `import_history` 记录数（全为 0 说明导入流程从未成功落库，重复点击也没用）；
- 旧版交接标记 `.cn_migration` 是否已落盘（已落盘表示产品把该批文件视为「已迁移」，重复触发导入不再搬运）；
- 旧版 `local.db` 的会话 / 消息条数——注意其**正文经产品侧加密**，本工具无法转成其它软件的原生格式，也**无法代 Qoder 完成导入**。

> 跨电脑迁移 Qoder，请使用本工具的**整库备份 / 还原**：Qoder 适配器已同时覆盖新旧两处数据根，不会漏掉任一侧。

## 7. 常见问题

- **还原后历史会话「看得到但点开没内容」**：通常是 6.1 的 UUID 死目录或 6.3 的长路径处理所致；跨用户场景确保本机已登录该工具。
- **还原后某些工作区变成「未分组」**：通常是 6.2 的全局索引被整体覆盖。本工具对支持合并的工具会保留并合并本机原有工作区。
- **DSH 升级后部分历史会话报 corrupt / 无法加载**：先点「检测会话健康」看原因（见 6.4）——旧格式会话用「修复未分组会话」处理；若被标记为「子代理描述符不兼容」，当前版本暂不修复，需等后续支持。
- **界面没有「AI 工具」下拉 / 显示旧样式**：说明你运行的不是最新打包的 exe。请重新 `build.bat` 打包，或用 `run.bat` 走源码模式。
- **备份包很大**：检查是否勾选了插件 / 设置；本地缓存与日志默认不列入备份。
- **还原后 CodeBuddy 自定义模型「看得到但无法调用」**：多为该模型的敏感凭证（apiKey / 令牌等）在备份时被脱敏占位（安全设计），还原后需你在目标机重新填入对应凭证（或确保目标机有对应的环境变量引用，如 `${MY_API_KEY}`）。
- **Qoder CN 新版用「导入旧数据」后仍看不到历史会话**：新版 Qoder CN 已改为独立桌面客户端（Electron），数据根从旧的 `~/.qoder-cn` 迁到 `%APPDATA%\com.qodercn.app.stable`（会话主库 `main.sqlite`）。设置里的导入入口只搬它认识的那部分数据，旧插件的部分记忆 / 项目数据**不会被自动带过去**，所以「导入成功」≠「历史可见」。本工具的 Qoder 适配器已同时覆盖新旧两处数据根，并对这种不一致给出诊断结论（提示哪一侧缺数据）；请以本工具的整库备份 / 还原作为跨电脑迁移手段。
- **想用别的软件的历史会话，但「导入会话…」按钮是灰的**：说明当前所选工具的会话主库是产品侧加密的（Qoder / TraeCode CN / TraeWork CN），或者其写出格式尚未实测（ZCode）。详见第 5.3 节。
- **导入会话后目标软件里看不到**：检查「数据导入」区点「导入说明」；WorkBuddy / DSH 需要落点与索引同时正确（本工具已自动登记索引），而 CodeBuddy 若目标 workspaceId 与源机器项目路径不一致，会写入但可能不被索引显示——导入完成时的「注意事项」框会提示这一点。
- **从 CodeBuddy 导入到 WorkBuddy，列表里明明显示有「工作区 xxxxxxxx」，落点却是 `~/WorkBuddy/<时间戳>`**：那个「工作区 xxxxxxxx」是 CodeBuddy 的 `workspaceId`，即 `md5(项目路径)`——**哈希不可逆**，不能当路径用；而 WorkBuddy 必须用**路径**。本工具会先把 id 还原成路径，只有能验证的才认：① **备份包自带的「会话原始工作区映射」**（导出时生成、随包携带，跨机有效且不依赖操作顺序）；② 本机 IDE 记过的「已打开工程」记录；③ **会话正文里出现过、且 `md5` 校验对得上的路径**。三条都失败才退到默认落点——**而且导入前会先弹框告诉你**（列出会话、点明会落到哪个默认目录），不会让你事后才发现；正文里的候选路径也会一并列出，选「否」改用「手动指定工作区」后下拉即可一键采用。
- **跨机还原后，导入的会话能不能回到原来的工程工作区**：能还原一部分，但**不是全部**。首选依据是**备份包自带的「会话原始工作区映射」**（只要备份时勾了「集中会话」，导出时会自动带上，还原后就是现成的）；其次是「IDE 工作区记录」；再其次是会话正文里的路径 + `md5` 校验。**如实说明**：本机实测 21 个工作区里只有 1 个能还原出具体路径（覆盖 9/31 条会话），其余工作区对应的工程目录早已不在磁盘上、正文里也没有它的完整形态——这类推不出来的会话，导入前会**明确弹框确认**（附候选路径），不再静默落到默认目录。
- **备份包里会不会带上我原来电脑的信息？能不能发给别人**：会带上**路径等信息**（会话正文里的绝对路径、归档结构里的用户名与登录用户标识、默认勾选的「IDE 工作区记录」，以及导出时自动附带的「会话原始工作区映射」）。这类信息是会话/记录本身自带的，也是还原后把数据归回原工作区的依据；但它确实会随包外传，**发给别人前请自行判断**。界面在「备份内容」那一行、备份完成提示、备份包详情三处都会写明具体带了哪些（详见 5.1）。
